# 数据迁移中心

## 目标与边界

数据迁移中心用于把公司原有 Excel 安全迁入软装项目采购经营财务系统。历史文件不会直接写入业务表，必须经过工作簿浏览、字段映射、关联解析、标准化、重复检测、业务校验、暂存预览和人工确认。

当前使用确定性规则，不调用 AI。代码只预留 `SemanticMappingProvider` 接口；未来 AI 只能返回字段建议、置信度和原因，不能写数据库。

## 两种模式

- 日常标准导入：下载标准模板、填写业务名称或编码、上传预检并确认导入。模板不再要求数据库 ID。
- 历史 Excel 迁移：直接上传原工作簿，选择 Sheet 和业务类型，配置或复用 Mapping，再进入暂存区。

系统支持公司、账户、客户、供应商、项目、合同、应收、收款、SKU、供应商报价、采购、应付、付款和发票 14 类业务对象。单个历史迁移 Sheet 最多 10,000 行，页面按 50 行分页预览，服务端按 250 行分段写入暂存区。

## 数据架构

| 表 | 作用 |
| --- | --- |
| `import_batches` | 批次号、公司范围、类型、Hash、行数和生命周期 |
| `import_files` | 原文件名、大小、Hash 和 Sheet 数 |
| `import_sheets` | Sheet 名、表头、前 10 行、原始行和选择状态 |
| `import_mapping_templates` | Sheet 特征、业务类型、字段映射和转换规则 |
| `import_staging_rows` | 原始行、标准行、问题、重复状态、处理动作和目标记录 |
| `import_reference_resolutions` | 名称/编码匹配状态、候选项和人工确认 |
| `entity_aliases` | 客户、供应商、项目等实体别名 |
| `import_data_lineage` | 正式记录到来源文件、Sheet、原始行和批次的血缘 |

批次号格式为 `IMP-YYYYMMDD-XXXX`，日期按 Asia/Shanghai 生成。批次 Hash 使用原文件 SHA-256；正式导入仍会对标准化数据计算 SHA-256，防止重复提交和预览后篡改。

## 映射规则

映射按以下顺序执行：

1. Sheet 表头签名精确匹配已保存 Mapping Template。
2. 系统字段名和别名字典精确匹配，例如 `工程名称 → 项目名称`、`甲方 → 客户`、`厂家 → 供应商`、`核价 → 最终采购单价`、`已打款 → 付款金额`。
3. 无法识别的字段保持“忽略”，由用户人工选择系统字段。

Mapping Template 按公司、业务类型和排序后的规范化表头唯一保存。人工确认一个可能匹配项后，系统将原值保存为 `entity_aliases`，相同公司以后可精确复用。

## 标准化规则

- 金额：支持 `￥1,200.00`、`1,200`、`1200`、`1.2万`、`12,000元`，正式库仍以整数分保存。
- 日期：支持 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD` 和 Excel Serial Date。
- 比例：`13%`、`0.13` 和 `13` 均标准化为百分数 13。
- 布尔：支持 `是/否`、`Y/N`、`yes/no`、`true/false` 和 `1/0`。
- 数量：支持整数和最多四位小数，必须大于 0。

金额、日期、比例、数量、布尔、唯一性和重复检测始终由程序处理，不交给 AI。

## 关联解析

`ImportReferenceResolver` 使用公司名称/编码、客户名称/编码、项目名称/编号、供应商名称/编码、SKU 编码、合同编号、账户名称/尾号、应收节点、采购单编号和应付编号解析内部 ID。

返回状态：

- `EXACT_MATCH`：唯一精确命中，可以继续。
- `POSSIBLE_MATCH`：唯一近似命中，黄色警告，必须人工确认。
- `MULTIPLE_MATCHES`：多个候选，红色阻断，必须人工选择。
- `NOT_FOUND`：未找到，红色阻断；可在主数据中创建后重新预检，或将该行设为跳过。

非老板角色只能读取和解析本公司实体。正式导入前还会再次执行现有的公司范围、项目关系、账户余额、应收/应付余额和金额安全检查。

## 重复规则

| 对象 | 业务键 |
| --- | --- |
| 公司 | `company_code` |
| 客户 | `company + customer_code` |
| 供应商 | `company + supplier_code` |
| 项目 | `project_code` |
| 合同 | `contract_number` |
| SKU | `project + sku_code` |
| 收款 | `receipt_number` |
| 付款 | `payment_number` |
| 发票 | `company + invoice_number` |

结果为 `NEW`、`EXISTING` 或 `POSSIBLE_DUPLICATE`。基础资料可跳过、匹配现有或作为新记录；合同、采购、应付、收付款和发票等财务事实默认跳过，系统禁止把已存在财务事实强制作成新记录覆盖原账。

## 暂存与正式导入

暂存行状态为 `READY`、`WARNING`、`ERROR`、`CONFIRMED`、`IMPORTED`、`SKIPPED` 或 `ROLLED_BACK`。用户可以在系统内修改问题字段、选择关联候选、调整重复处理动作，或导出错误行 Excel。

只有红色错误为 0 时才能人工确认。黄色警告经人工确认后变为 `CONFIRMED`。正式导入在单个数据库事务中完成业务记录、审计日志、暂存状态、数据血缘、旧导入日志和批次状态更新；任何语句失败会整体回滚。

业务详情中的“数据来源”显示来源文件、Sheet、原始行和导入批次。原始 JSON 保留在血缘记录中用于查账。

## 回滚机制

已完成批次可以请求整批撤销。系统先检查每条正式记录是否被下游表引用；存在审批、采购单、收付款、发票分摊、库存等引用时停止撤销并列出阻断记录。

无下游引用时在一个事务中删除该批正式记录，将暂存行和批次标记为 `ROLLED_BACK`，并写入审计日志。收款和付款撤销会先恢复应收/应付累计和账户余额。血缘记录保留，作为曾导入和已撤销的证据。

## 推荐试运行

按公司/账户 → 客户/供应商 → 项目 → 合同 → 预算/SKU → 应收 → 报价/采购 → 应付 → 收款 → 付款 → 发票 → 库存/退换货迁移。

仓库 `tests/fixtures/data-migration` 提供 5 套多 Sheet/旧表头样本：项目总表、SKU 预算、采购明细、应收收款、供应商应付付款。先替换为 3-5 份脱敏真实样本验证 Mapping，再迁移 2-3 个真实项目，并逐项对比合同、应收、采购、应付、收付款、欠票和资金余额。

## 自动化覆盖

当前测试覆盖模板/别名 Mapping、金额、日期、比例、布尔、四位小数数量、名称与关联解析、重复检测、错误阻断、公司权限隔离、Mapping Template、原子写入、批次状态、数据血缘和安全撤销。
