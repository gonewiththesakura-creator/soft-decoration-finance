- Phase 1：公司、账户、客户、供应商、项目
- Phase 2：合同、应收节点、质保金状态和收款联动
- Phase 3：SKU、多供应商报价、核价状态和采购申请
- Phase 4：采购审批、采购单、应付、付款申请、付款审批和付款记录
- Phase 5：发票台账、Excel 预检/导入/导出、操作日志
- Phase 6：老板首页、未来 30 天收支、逾期、欠票和预算异常
- Phase 7：只读 AI Query Service 与结构化经营回答

- 预算版本和项目变更记录
- 退货记录及采购订单/应付冲减 Seed 案例
- 桌面、平板和手机响应式布局
- 隔离数据库上的自动化业务测试

- 审计款最终金额的独立调整工作台
- 质保到期的定时任务，目前查询时动态计算释放状态

- 采购取消、换货、退款和已付款冲销的完整交互工作台
- Excel 超大文件异步队列和导入任务重试
- 邮件、企业微信或钉钉通知
- OpenAI API 接入，目前 AI Service 为确定性只读查询实现

## 已知问题

- 本地数据库是单机嵌入式 PostgreSQL，同一数据目录只能由随应用启动的数据库服务访问。
- 集团 Seed 数据用于演示，不能直接作为正式客户、供应商或财务数据。
- 第一版不存储附件二进制，仅预留业务结构。
- 发票欠票状态的精细核销仍以应付级状态为主，未实现发票与应付多对多分摊。
- 退货已能形成记录并冲减订单/应付，库存和退款的全链路需在二期完成。

## 二期建议

1. 迁移托管 PostgreSQL、对象存储和定时备份，支持多实例部署。
2. 建立附件中心、银行回单与审批证据链。
3. 完成预算变更联动规则、审计款调整和质保金自动释放任务。
4. 增加采购取消、退换货、退款、付款冲销和库存流水工作台。
5. 建立进销项发票与应收/应付的明细核销关系。
6. 接入 OpenAI Responses API，以现有只读工具接口提供自然语言查询。
7. 增加消息通知、审批 SLA、异常订阅和月度经营快照。
