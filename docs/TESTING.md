# 测试说明

运行：

```bash
npm test
```

测试启动器会创建临时目录、Seed 一套独立 PostgreSQL 数据、启动唯一数据库服务、执行测试并清理临时目录，不会污染开发或试点数据。

## 自动化覆盖

- 财务、采购、设计师资源权限矩阵
- 项目经理只能看到成员表授权的 4 个项目
- 公司范围不会返回其他公司项目
- 采购申请审批后原子生成采购单和应付
- 采购审批生成操作日志
- 收款后应收余额和公司账户余额同步更新
- 付款申请审批与实际付款分离
- 付款后应付余额和公司账户余额同步更新
- Excel 缺列/必填错误在预检阶段拦截
- 金额以整数分格式化，无浮点尾差

## 手工验收

1. 使用老板账号登录并切换三家公司，核对首页资金合计。
2. 打开任一项目，逐个检查合同、应收、SKU、采购、应付、付款、发票、预算、变更和日志页签。
3. 新建采购申请，确认初始状态为“待审批”。
4. 老板审批通过，核对采购单和应付各增加一条。
5. 新建付款申请，老板审批后由财务登记付款，核对应付和账户余额。
6. 登记客户收款，核对应收和收款账户余额。
7. 上传一个缺少必填列的 Excel，确认只显示错误且正式表无新增记录。
8. 以项目经理账号登录，确认只显示参与项目。
9. 在 390×844 视口检查侧栏、首页和审批按钮。
