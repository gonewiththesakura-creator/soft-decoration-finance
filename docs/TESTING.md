# 测试说明

运行：

```bash
npm test
```

测试启动器会创建临时目录、Seed 一套独立 PostgreSQL 数据、启动唯一数据库服务、执行测试并清理临时目录，不会污染开发或试点数据。

## 自动化覆盖

- 财务、采购、项目经理、设计师的读写权限矩阵和公司/项目范围
- 采购申请审批后原子生成采购单和应付，审批意见必填
- 收款、付款、撤销和冲销对业务余额与账户余额的联动
- 财务金额 `NUMERIC(18,0)` 与数量 `NUMERIC(18,4)` 迁移结果
- 安全编辑的业务状态限制及 before/after Audit Log
- Excel 必填、唯一性、外键、范围、重复导入和事务回滚
- 登录失败限流与登录日志
- 采购/付款审批详情完整性和职责分离
- 退换货库存流水、发票与应付明细核销
- 已通过付款申请不超过当前应付余额

## 手工验收

1. 老板登录并切换三家公司，核对首页六项指标和资金等式。
2. 打开采购审批详情，核对 SKU、图片、比价、预算偏差、费用、条款、附件和历史意见。
3. 老板填写意见审批付款，确认页面没有执行付款入口。
4. 财务登录后打开已通过付款，核对余额、欠票和银行回单字段，再执行付款。
5. 新建和编辑未审批业务，确认已生效业务只能作废、撤销或冲销。
6. 上传包含错误及重复数据的 Excel，确认正式表无部分写入。
7. 用项目经理、设计师账号验证项目范围和财务写入限制。
8. 在 390 x 844 视口检查侧栏、首页、表格横向滚动和审批详情。
