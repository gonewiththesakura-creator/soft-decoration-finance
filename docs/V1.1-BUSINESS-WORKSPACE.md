# 织衡经营财务 V1.1 业务工作台

## 版本目标

V1.1 在 V1.0 主业务链上补充日常工作入口、详情页、业务关系和真实附件，不改变审批、财务事务、金额精度、权限范围与审计机制。

## 新增页面

- `/procurement-workspace`：按 SKU 集中询价、比价、选供和批量发起采购申请。
- `/finance-workspace`：集中展示今日应收、应付、逾期、已审批待付款、欠票和账户余额。
- `/customers/[id]`：客户项目、合同、应收、收款、发票和附件档案。
- `/suppliers/[id]`：供应商报价、采购、应付/付款、发票、退换货和附件档案。
- `/purchase-requests/[id]`、`/purchase-orders/[id]`、`/payables/[id]`、`/payments/[id]`、`/contracts/[id]`：业务单据详情、关系、附件和时间线。
- `/permissions`：岗位读写权限矩阵。

项目详情重组为十个业务 Tab，并在概览集中展示收入、采购、财务台账，五项经营进度和八类规则风险。

## 附件系统

新增 `attachments` 表和 `0006_attachment_system` 迁移。附件记录包含公司、项目、业务对象、分类、文件元数据、存储键、上传人和作废信息。

开发环境由 `LocalStorageService` 写入 `UPLOADS_DIR`（默认 `/uploads`）。业务层只依赖 `StorageService` 接口，后续可替换为 S3、OSS、COS 或 MinIO。文件内容通过鉴权 API 读取，不暴露本地路径。

支持 PDF、JPEG、PNG、WebP、XLSX 和 DOCX，单文件上限 10 MB。上传、预览、下载和作废均受原业务对象权限控制；作废保留文件和审计证据。

## 流程变化

### 采购

采购人员可在一个工作台完成 SKU 筛选、查看全部报价、确定供应商、多选同公司/同项目/同供应商 SKU、补充说明与付款方式并提交审批。申请金额由报价、数量、运费和安装费计算，不重复录入。

### 财务

财务人员进入工作台即可按时间优先级处理应收、应付、已审批付款和发票缺口。快捷操作可直接打开收款或发票新增表单。执行付款必须先上传真实银行回单。

### 业务关系

项目、客户、供应商、合同、采购申请、采购订单、应付和付款列表可进入详情。单据详情显示上游与下游对象、统一附件和来自真实审批、订单、到货、收付款及审计记录的时间线。

## 导航变化

主导航调整为首页、项目、采购、财务、基础资料和系统。V1.0 的原有资源页及路由继续保留，但不再全部占用显眼入口。AI 页面未纳入 V1.1 导航。

## 测试结果

自动化测试从 17 项增至 23 项。新增覆盖：

- 项目经营聚合与时间线
- 采购工作台直接生成采购申请
- 财务工作台公司范围汇总
- 客户与供应商档案聚合
- 单据关系与业务时间线
- 附件上传、读取、作废、审计和写权限

交付前执行：

```text
npm run typecheck
npm run lint
npm test
npm run build
```

## 未完成项

- S3 compatible 存储适配器未启用，仅保留接口边界。
- 真实项目试运行需要业务侧提供并确认实际项目与资料，开发数据不冒充真实经营数据。
- 旧 URL 字段保留在数据库中用于兼容历史记录；V1.1 用户界面不再提供手工 URL 输入。

## 真实项目试运行建议

上线前选择三个项目并为每个项目指定项目经理、采购和财务验收人：

1. 正常项目：验证合同、应收、收款、选供、采购申请、订单、应付、付款和发票完整闭环。
2. 变更项目：至少包含一次增减项或换品，并验证预算版本、退换货及冲销。
3. 复杂结算项目：至少包含分期付款、供应商欠票和质保金节点，并验证风险提示和未来 30 天现金安排。

每个项目需上传真实合同、报价单、产品图片、采购附件、银行回单和发票样本。试运行结束后核对项目总账与原始单据，并由三类岗位分别确认操作路径是否顺畅。
