# V1.7 Real Data Pilot

## 目标

V1.7 将系统从 Demo 展示切换到可控的真实数据试运行。`DATA_MODE=real` 是默认值；启动过程只保证数据库结构和老板管理员存在，不自动写入公司、项目、账户、供应商或财务事实。

## 运行模式

- `real`：默认模式。禁止 Demo Seed；没有业务数据时，驾驶舱、财务和采购页显示导入引导，不生成零值经营结论。
- `demo`：仅供隔离演示和自动化测试。只有 `npm run db:seed:demo` 会写入演示业务数据。
- `npm run db:seed` 保留为 `db:bootstrap` 的兼容别名，不再创建演示数据。

生产空库必须配置：

```env
DATA_MODE=real
BOOTSTRAP_OWNER_NAME=系统管理员
BOOTSTRAP_OWNER_EMAIL=owner@example.com
BOOTSTRAP_OWNER_PASSWORD=replace-with-a-strong-password
IMPORT_STORAGE_DIR=./data/imports
IMPORT_ALLOWED_ROOTS=D:\BusinessData\SoftDecoration
REAL_DATA_BACKUP_DIR=./backups
```

## 安全清空

停止应用后执行 `npm run data:reset-real`。命令会先打印业务表行数，并要求逐字输入：

```text
RESET_TO_REAL_DATA
```

确认后，命令先通过 PGlite `dumpDataDir("gzip")` 创建完整数据库压缩备份，同时写入包含时间、数据库路径、表计数、保留管理员和 SHA-256 的 `manifest.json`。随后在事务中清空业务、导入、审计与 AI 运行数据，保留一个老板管理员，并逐表验证业务记录为零。数据库服务仍在运行、模式不是 `real` 或口令不匹配时均拒绝执行。

## 数据迁移中心

两种来源共享同一套暂存、人工确认、事务写入和回滚链路：

- 上传文件：支持一次选择或拖入最多 20 个 `.xlsx`、`.xls`、`.csv` 文件；每个文件建立独立批次。
- 扫描文件夹：仅老板可调用服务端 Node.js 文件系统；目录必须位于 `IMPORT_ALLOWED_ROOTS`，拒绝 UNC、磁盘根目录、系统目录、隐藏目录、符号链接与 `..` 穿越。
- 扫描限制：最多 250 个文件、单文件 30MB、总大小 500MB、15 秒超时；扫描只读，不复制、移动或修改源文件。
- 文件状态：`NEW`、`UPDATED`、`UNCHANGED`、`DUPLICATE`、`UNSUPPORTED`、`ERROR`。
- 每个受支持文件计算 SHA-256，并保存来源路径、扩展名、大小、mtime、工作簿结构、版本组、版本号和当前版本标识。
- 原始文件进入暂存时复制到 `IMPORT_STORAGE_DIR` 管理存储；正式写入前仍需映射、校验和人工确认。

Sheet 分类枚举为 `PROJECT_SUMMARY`、`CONTRACT`、`PROJECT_COST`、`SKU_DETAIL`、`SUPPLIER_QUOTE`、`PURCHASE_ORDER`、`PAYABLE`、`PAYMENT`、`RECEIVABLE`、`RECEIPT`、`INVOICE`、`REFERENCE`、`EMPTY`、`UNKNOWN`。规则结果带置信度和警告，允许人工选择业务类型；AI 不参与财务写入决策。

## 证据与重复控制

- 预览最多显示前 50 行，并保留实际 Excel 行号。
- 文件级重复由 SHA-256 判定；业务级重复继续按各业务对象唯一键判定。
- 汇总 Sheet 与明细 Sheet 的同一成本项记录为一个 `Business Fact`，来源分别进入多条 `Source Evidence`，不把汇总金额和明细金额再次相加。
- 正式数据血缘保留批次、原文件、Sheet、行、Mapping Template、目标表与目标记录；业务事实证据模型预留列/单元格定位。
- 真实模式确认预检结果必须输入“确认导入真实数据”。正式导入在单一事务内执行；失败回滚全部写入。已完成批次只有在不存在下游引用时才能撤销。

## 验收状态

自动化已覆盖：真实空库启动、带备份的安全重置、上传暂存、文件未变化/更新/重复识别、空与未知 Sheet、青岛样本等价 Sheet 分类、汇总/明细单一事实多证据、事务失败回滚、导入批次撤销、非老板扫描拒绝和路径穿越拒绝。

指定样本 `1.青岛鑫江中心成本表（2023-5-13更新）未完结(1).xlsx` 当前未在本机可访问目录中发现，因此尚未执行真实样本的人工上传、Mapping 确认和正式导入。代码不会自动寻找并导入该文件。完成最终试点需要：

1. 将样本放入上传选择范围或 `IMPORT_ALLOWED_ROOTS`。
2. 由用户在迁移中心核对 Sheet 分类、字段映射、重复项与错误行。
3. 用户输入“确认导入真实数据”，再执行正式导入。
4. 对照项目、供应商、采购、应付和财务页，抽查数据血缘与汇总口径。

## 当前边界

V1.7 不提供任意磁盘浏览、后台自动导入、OCR、AI 自动写库或跨文件夹移动。大文件断点续传、病毒扫描、对象存储和外部 PostgreSQL 仍属于后续生产加固范围。
