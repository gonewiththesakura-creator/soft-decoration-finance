# V1.7.1 外部真实数据提交接口

## 安全边界

外部客户端可以把 `.xlsx`、`.xls` 或 `.csv` 文件提交到统一迁移管线。接口完成上传、SHA-256、格式验证、Sheet 解析、分类和批次创建后停止，状态保持 `UPLOADED`。它不提供 Confirm 或 Import 操作，也不会直接写入公司、项目、供应商、SKU、收付款等正式业务表。

正式写入必须由 Owner 登录系统并打开 `/imports`，依次完成 Sheet Review、Mapping、Staging Validation 和 Preview，然后输入：

```text
确认导入真实数据
```

确认后才能在数据迁移中心执行正式导入。

## 配置

在运行服务器的 `.env.local` 配置长随机 Token，不要使用 `NEXT_PUBLIC_` 前缀：

```dotenv
DATA_MODE=real
REAL_DATA_INGEST_TOKEN=replace-with-a-long-random-secret
REAL_DATA_INGEST_REQUESTS_PER_MINUTE=10
REAL_DATA_INGEST_FILES_PER_HOUR=100
```

修改环境变量后必须重启应用。Token 只用于服务器端常量时间校验，不进入浏览器、响应或日志。

## 文件提交

```http
POST /api/real-data/ingest/files
Authorization: Bearer <REAL_DATA_INGEST_TOKEN>
Idempotency-Key: <client-generated-key>
Content-Type: multipart/form-data
```

表单字段支持单文件 `file` 或多文件 `files`。限制为每次 20 个文件、单文件 60MB、请求 200MB；默认限流为每分钟 10 个请求、每小时 100 个文件。扩展名、MIME 和实际容器结构会共同检查，文件名会清理，工作簿公式、宏、DDE 和外部链接不会执行，原文件不会发送给 AI。

V1.7.2 增加数据归属字段：`scope=PROJECT` 时必须同时传 `projectId`，或传 `projectName` 并按需设置 `createProject=true`。缺少项目上下文会返回 `PROJECT_CONTEXT_REQUIRED`，不会创建批次。`scope=COMPANY` 可传 `companyId`，`scope=MASTER` 不要求项目。

相同 `Idempotency-Key` 重试返回第一次保存的响应，不新建批次。相同 SHA-256 会返回 `fingerprintStatus: UNCHANGED` 和 `duplicateOfBatchId`；仍可留下新的提交审计，但不会自动写入正式业务事实。

### curl

```bash
curl -X POST "http://127.0.0.1:3001/api/real-data/ingest/files" \
  -H "Authorization: Bearer YOUR_REAL_DATA_INGEST_TOKEN" \
  -H "Idempotency-Key: test-001" \
  -F "scope=PROJECT" \
  -F "projectName=青岛鑫江中心" \
  -F "createProject=true" \
  -F "files=@D:/真实数据/青岛鑫江中心成本表.xlsx"
```

### Windows PowerShell

```powershell
curl.exe -X POST "http://127.0.0.1:3001/api/real-data/ingest/files" `
  -H "Authorization: Bearer YOUR_REAL_DATA_INGEST_TOKEN" `
  -H "Idempotency-Key: test-001" `
  -F "files=@D:/真实数据/青岛鑫江中心成本表.xlsx"
```

### Python

```python
import requests

with open(r"D:\真实数据\青岛鑫江中心成本表.xlsx", "rb") as f:
    response = requests.post(
        "http://127.0.0.1:3001/api/real-data/ingest/files",
        headers={
            "Authorization": "Bearer YOUR_REAL_DATA_INGEST_TOKEN",
            "Idempotency-Key": "qingdao-001",
        },
        files={"files": f},
        timeout=120,
    )

print(response.json())
```

成功响应中的 `batchId` 用于查询，并对应数据迁移中心里的批次。

## 状态与批次查询

```bash
curl "http://127.0.0.1:3001/api/real-data/ingest/status" \
  -H "Authorization: Bearer YOUR_REAL_DATA_INGEST_TOKEN"

curl "http://127.0.0.1:3001/api/real-data/ingest/batches/101" \
  -H "Authorization: Bearer YOUR_REAL_DATA_INGEST_TOKEN"
```

状态接口返回 `businessDataEmpty` 以及公司、项目、供应商、客户和 SKU 数量。批次接口返回数据归属、目标项目、冲突、自动分析摘要、业务事实置信度、文件 Hash、Sheet 分类、Mapping/暂存状态、可导入/警告/错误行数、是否已导入和创建时间，不返回原始行内容。

## 本机地址边界

`http://127.0.0.1:3001` 只能由运行系统的这台电脑访问。其他电脑、云端自动化服务或 ChatGPT 不能直接访问该地址。本版本不会开放不安全的公网端口；远程提交需要把系统部署到可访问服务器，或使用受控的 VPN/安全反向代理。

## 清空真实库

停止应用后执行：

```bash
npm run data:reset-real
```

输入 `RESET_TO_REAL_DATA` 后，脚本先将 PGlite 数据库、附件目录和受管导入原文件复制到时间戳备份目录，再清空业务、导入、审计和 AI 运行数据。脚本保留一个 Owner，并逐表验证业务数据为零。清空后不会 Seed 或导入任何样本。
