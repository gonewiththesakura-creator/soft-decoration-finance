# V1.7.2 项目级智能导入

## Scope model

上传先进入 `PENDING`，然后由用户确认 `PROJECT`、`COMPANY` 或 `MASTER`。项目数据必须绑定 `project_id`；公司级数据绑定 `company_id`；供应商和客户等共享主数据不使用项目作为唯一性范围。系统仍使用一个本地 PostgreSQL/PGlite 数据库，通过外键做逻辑隔离，不为项目创建独立数据库文件。

## Project binding

项目导入必须在 Staging 前选择已有项目或创建项目。创建项目时项目名称必填，项目编号可自动生成；公司和客户允许后续补充。绑定完成后，`project_id` 会贯穿 `import_batches`、`import_files`、`import_sheets`、`import_business_facts`、`import_business_fact_evidence`、`import_staging_rows` 和 `import_data_lineage`。正式写入前会再次校验批次、暂存行和目标业务记录的项目一致性。

## Auto detection

本地确定性分析器综合文件名、一级目录、文档标题、Sheet 名、表头和最多前 100 行项目字段。项目候选只作为建议，必须由用户确认。Sheet 分类保留为辅助信号，最终模型允许一个 Sheet 产生多个业务事实。

## Business Fact Engine

当前识别 `PROJECT`、`CONTRACT`、`PROJECT_COST`、`SKU`、`SUPPLIER`、`CUSTOMER`、`PURCHASE_ORDER`、`PURCHASE_ORDER_LINE`、`PAYABLE`、`PAYMENT`、`RECEIVABLE`、`RECEIPT`、`INVOICE`、`TAX` 和 `PAYMENT_TERMS`。一个事实保存结构化 payload 和业务 key，多处汇总/明细来源保存为 Evidence，避免把同一事实重复记账。

## Confidence

- `HIGH`: 置信度不低于 90%，自动接受并可进入 Staging。
- `MEDIUM`: 70%-89%，显示建议并要求确认。
- `LOW`: 低于 70%，必须确认或忽略。
- `CONFLICT`: 项目候选与目标项目强冲突，默认阻断。

字段别名精确匹配为高置信映射；包含关系等近似匹配只作为中置信建议。必填字段校验发生在识别目标业务类型之后。

## AI fallback

V1.7.2 的默认路径完全由本地规则完成。未来 AI 只处理 UNKNOWN、LOW 或 AMBIGUOUS 项，并且只接收脱敏的文件名、Sheet 名、表头、少量样本和结构统计。AI 只能提出分类、Mapping、事实或项目候选建议，不能创建正式项目、合并项目或写入正式财务数据。

## Project conflict

高置信候选与当前项目不等价时，批次进入 `PROJECT_CONFLICT`。用户可以切换项目，或明确选择“仍归入当前项目”；未处理冲突时不能 Staging、确认或正式导入。行内项目字段如果指向其他项目，也会生成阻断错误。

## Master data

Supplier 和 Customer 继续作为共享主数据。供应商重复判断使用公司、名称/编码及别名，不使用 `project_id`；SKU 和项目业务事实的重复判断包含项目范围。因此同一供应商可关联多个项目，而相同 SKU 编码可在不同项目独立存在。

## Folder project detection

文件夹扫描保持只读。扫描结果按一级目录汇总 Project Candidate，并显示每个候选下的文件数量。目录名不会直接创建项目，仍需与内容和已有项目匹配后由用户确认。

## Advanced mapping

默认界面展示候选项目、识别事实、导入计划、置信度和待确认项。原有业务类型、Mapping Template 与逐字段 Mapping 收纳在“高级字段映射”中，作为规则未覆盖时的人工回退能力。

## Lineage

原文件保存 SHA-256、版本、来源渠道和项目。项目详情的“原始文件”与“导入记录”页签可按项目追溯批次。正式记录的 lineage 保存批次、项目、文件、Sheet、源行、Mapping 模板、Evidence 角色和原始行快照。

## External API

`POST /api/real-data/ingest/files` 支持：

```text
scope=PROJECT
projectId=<existing id>
```

或：

```text
scope=PROJECT
projectName=青岛鑫江中心
createProject=true
```

项目范围缺少 `projectId` 和 `projectName` 时返回 `PROJECT_CONTEXT_REQUIRED`。接口只完成解析、分析和批次创建，正式导入仍需在迁移中心经过 Staging、人工确认和确定性事务写入。

## Acceptance boundary

自动化 QA 验证项目上下文、项目创建/复用、文件名候选、多事实识别、置信度、冲突阻断、项目级 Staging、项目级 Lineage、供应商共享与 A/B 项目隔离。实现 QA 通过不代表真实数据验收通过；第一份青岛鑫江中心真实工作簿仍需用户在 Preview 后核对合同、成本、SKU、采购、应付、付款与发票口径。
